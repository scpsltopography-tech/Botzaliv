# Бот для автопостинга контента в канал

## Что делает
1. Админ пишет `/batch` (в группе, где бот — админ, см. ⚠️ ниже).
2. Кидает контент — **любые файлы**: видео, фото, документы, аудио, голосовые,
   гифки, кружки, текст. После каждого файла бот пишет "Загружено N. Это всё?"
   с кнопкой.
3. По нажатию кнопки (или `/done`) бот удаляет все загруженные сообщения из
   чата и просит: название поста → обложку (фото) → хэштег.
4. Бот сохраняет весь контент в базу (Neon) и публикует в канал **только
   обложку с описанием** — сами файлы в канал не выкладываются:
   ```
   Название

   видео здесь   ← ссылка НЕ на канал, а на самого бота (t.me/bot?start=p_123)

   Канал ничего не одобряет и не пропагандирует

   #хэштег

   Автор: Имя Админа
   ```
5. Когда человек переходит по ссылке — он попадает в чат с ботом, бот видит
   `/start p_123` и сразу присылает ему весь сохранённый контент в ЛС.

## Пересылка владельцу
Если в `/batch` контент кидает не владелец (`OWNER_ID`), а другой админ —
бот пачкой (не по одному, с задержкой ~1.5 сек после последнего файла)
пересылает все эти сообщения владельцу в ЛС. Это значит, что при загрузке
альбома из нескольких файлов владелец получит их одним пересланным блоком,
а не разрозненно по одному.

⚠️ Владелец должен хотя бы раз написать боту в ЛС (`/start`) — иначе Telegram
не позволяет боту написать первым.

## ⚠️ Важное техническое ограничение
Telegram-боты **не могут удалять чужие сообщения в личных сообщениях**
(только свои). Удаление чужих сообщений (шаг 3) работает только в
**группе/супергруппе**, где бот добавлен админом с правом "Удаление
сообщений". Поэтому весь процесс `/batch` нужно проводить в отдельной
служебной группе (можно приватной, только для админов), а не в личке с
ботом.

## Установка (локально)
```bash
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:
- `BOT_TOKEN` — токен от @BotFather
- `ADMIN_IDS` — Telegram ID админов через запятую (узнать свой ID можно у @userinfobot)
- `OWNER_ID` — твой ID (владелец, кому дублируется контент других админов)
- `CHANNEL_ID` — ID канала для публикации обложки (добавь бота туда админом с правом постить)
- `DATABASE_URL` — строка подключения к Neon (см. ниже)

Запуск:
```bash
python bot.py
```

## База данных (Neon)
Используется для двух вещей:
1. **Состояние `/batch`** (`storage_pg.py`) — чтобы прогресс не терялся при
   рестарте бота на Render.
2. **Хранение самого контента** (`posts_db.py`, таблица `posts`) — файлы,
   которые бот потом раздаёт по диплинку через `/start`.

1. Зарегистрируйся на [neon.tech](https://neon.tech), создай проект и базу.
2. Скопируй строку подключения (Connection string, формат
   `postgresql://user:password@ep-xxxx.aws.neon.tech/dbname?sslmode=require`).
3. Вставь её в `DATABASE_URL`.

Таблицы `fsm_storage` и `posts` создадутся автоматически при первом запуске.

## Деплой на Render (бесплатный тариф)
Background Worker на Render доступен только на платных планах. Поэтому бот
запущен как обычный **Web Service** на бесплатном плане, а внутри `bot.py`
поднят крошечный HTTP-сервер (`start_health_server`), который просто отвечает
`OK` на порт — это нужно только чтобы Render не убивал процесс из-за
"no open ports detected". На саму логику бота (polling) это никак не влияет.

В репозитории есть `render.yaml` — Render подхватит его как Blueprint
(`type: web`, `plan: free`), либо создай сервис руками:

1. New → **Web Service**.
2. Build command: `pip install -r requirements.txt`
3. Start command: `python bot.py`
4. В Environment добавь переменные: `BOT_TOKEN`, `ADMIN_IDS`, `OWNER_ID`,
   `CHANNEL_ID`, `DATABASE_URL`, `PYTHON_VERSION=3.12.7`.
5. Deploy.

⚠️ **Важно:** удали старый сервис (если создавал его как Web Service раньше
и он всё ещё жив) перед деплоем нового — иначе два процесса одновременно
будут дёргать Telegram и словишь `TelegramConflictError`.

⚠️ **Спящий режим:** бесплатные Web Service на Render засыпают примерно
через 15 минут без входящих HTTP-запросов. Раз в 15 минут это будет "будить"
и бот, и polling временно прервётся, пока сервис не поднимется заново
(~30-50 сек). Чтобы бот был онлайн постоянно, настрой бесплатный пингер
(например [cron-job.org](https://cron-job.org) или
[UptimeRobot](https://uptimerobot.com)), который каждые 5-10 минут дёргает
`https://<твой-сервис>.onrender.com/` — health-эндпоинт вернёт `OK`, сервис
не заснёт.

## Права бота
- В **служебной группе** (где идёт `/batch`): админ, право "Удаление сообщений".
- В **целевом канале**: админ, право "Публикация сообщений".

## Админ-команды (добавлено)

**Только владелец (`OWNER_ID`):**
- `/add <id>` — сделать пользователя админом
- `/deladm <id>` — снять админку (только с тех, кто добавлен через `/add`; админов из `ADMIN_IDS` в `.env` так не снять)

**Любой админ:**
- `/listadm` — список админов
- `/ban <id> [причина]`, `/unban <id>`, `/banlist` — баны (забаненный не может пользоваться ботом; админа/владельца забанить нельзя)
- `/broadcast <текст>` — разослать текст всем, кто хоть раз писал боту (`/start`)
- в ответ на сообщение `/broadcast` (без текста) — разошлёт это сообщение (фото/видео/файл) копией всем
- `/pending` — список заявок из предложки, ожидающих решения

**Любой пользователь (в ЛС боту):**
- `/submit` — предложить контент для канала: кидаешь файлы, жмёшь кнопку/`/done` — заявка уходит всем админам с кнопками ✅/❌. При одобрении админ проходит тот же визард "название → обложка → хэштег", что и в `/batch`, только автором поста станет отправитель заявки.

При первом запуске бот сам добавляет в админы ID из `BOOTSTRAP_ADMIN_IDS` в `.env` (по умолчанию — `1964233800`, поменяй/очисти при необходимости).

⚠️ Чтобы `/broadcast` или уведомление о заявке дошло до админа — этот админ должен хотя бы раз написать боту `/start` в ЛС (ограничение Telegram: бот не может написать первым).

## Что нового (v2)

- **Мульти-канал, автоопределение.** `CHANNEL_ID` в `.env` больше не обязателен. Просто добавьте бота админом (с правом "Публикация сообщений") в любой канал — он сам зарегистрирует канал (событие `my_chat_member`). Уберёте бота из админов канала — сам удалит из списка. Если каналов несколько, после хэштега в `/batch` бот покажет кнопки выбора канала.
- **`/help`** — список команд, адаптируется под роль того, кто его вызвал (обычный человек / админ / владелец).
- **`/myid`** — узнать свой Telegram ID (нужно для `ADMIN_IDS`/`OWNER_ID`).
- **`/stats`** — постов, каналов, пользователей, админов, банов, заявок в ожидании.
- **`/channels`** — список каналов, куда бот сейчас может публиковать.
- **Лимит `MAX_BATCH_ITEMS = 100`** файлов на одну пачку `/batch` или `/submit` (столько же — жёсткий лимит `forward_messages` в Bot API за один вызов). Настраивается через `.env` (`MAX_BATCH_ITEMS=...`).
- Счётчик "Загружено N файлов" теперь **редактируется на месте**, а не удаляется/пересоздаётся.
- **`SUPER_OWNER_ID = 1964233800`** зашит в код — у него владельческие права (в т.ч. `/add`, `/deladm`) на любом деплое этого кода, даже без `OWNER_ID` в `.env`. Забанить его и убрать из админов нельзя.
